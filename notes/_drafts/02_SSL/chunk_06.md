## Pretext Task5: Rotation Prediction (p.41)

**슬라이드 내용**
- No labels are needed, The applied rotation becomes the label.
- 그림: 왼쪽에 원본 이미지 X (파란 새가 나뭇가지에 앉은 사진). 여기서 4개 분기 화살표가 나가 각각 변환 함수 $g(X, y=0)$ "Rotate 0 degrees", $g(X, y=1)$ "Rotate 90 degrees", $g(X, y=2)$ "Rotate 180 degrees", $g(X, y=3)$ "Rotate 270 degrees" 로 들어감. 각 출력은 회전된 이미지 $X^0, X^1, X^2, X^3$ ("Rotated image").
- 4개의 회전 이미지는 각각 같은 구조의 "ConvNet model F(.)" (사다리꼴 블록)로 들어가고, 오른쪽 점선 박스 "Objectives:" 안의 초록 박스 "Maximize prob. $F^0(X^0)$ / $F^1(X^1)$ / $F^2(X^2)$ / $F^3(X^3)$" 로 연결됨. 각각 "Predict 0 degrees rotation (y=0)", "Predict 90 degrees rotation (y=1)", "Predict 180 degrees rotation (y=2)", "Predict 270 degrees rotation (y=3)".
- 출처: Gidaris et al., ICLR 2018, UNSUPERVISED REPRESENTATION LEARNING BY PREDICTING IMAGE ROTATIONS

**설명**
- **Rotation Prediction (RotNet)**: 이미지를 0°, 90°, 180°, 270° 중 하나로 무작위 회전시킨 뒤, 어느 각도로 회전됐는지를 맞히는 **4-class classification** 문제로 푸는 pretext task. 회전 각도 자체가 label이 되므로 사람이 만든 annotation이 필요 없음.
- 기호: $X$ = 원본 이미지, $g(X, y)$ = $y \in \{0,1,2,3\}$ 에 대해 $y \times 90°$ 만큼 회전시키는 변환, $F^y(\cdot)$ = ConvNet이 출력하는 y번째 회전 클래스의 확률(softmax output). 목적함수는 올바른 y에 대한 확률 $F^y(g(X,y))$ 를 maximize 하는 것, 즉 cross-entropy 최소화와 같음.
- 이전 pretext task(jigsaw, inpainting, colorization 등)와의 차이: 입력에 인위적 변환 하나만 가하면 되므로 **구현이 매우 단순**하고, 정답이 정확히 4가지로 고정돼 있어 chance level(25%)이 명확하고 학습이 안정적임. jigsaw처럼 permutation 수가 많거나 inpainting처럼 픽셀 복원이 필요하지 않음.
- 왜 representation이 좋아지는가: 회전을 맞히려면 모델이 이미지 속 **object의 위치·자세·"위/아래" 개념**(예: 새의 머리는 위쪽, 하늘은 위, 땅은 아래)을 인식해야 함. 즉 object를 먼저 localize하고 category/semantic을 파악해야 하므로 object-centric feature가 학습됨.
- > 보충: 원 논문(Gidaris, Singh, Komodakis, ICLR 2018)은 RotNet이라는 이름을 쓰고, 학습 시 한 이미지의 4가지 회전 버전을 한 batch에 함께 넣어 학습함. 또 회전을 flip/transpose 연산으로 구현하므로 가장자리 경계 같은 trivial한 low-level artifact 단서가 생기지 않는다는 점이 장점으로 언급됨(45° 같은 임의 각도 회전과 대비). 이 부분은 슬라이드에 없는 일반 지식임.

## Pretext Task5: Rotation Prediction (p.42)

**슬라이드 내용**
- Rotation prediction accuracy.
- 캡션: "Table 2: Exploring the quality of the self-supervised learned features w.r.t. the number of recognized rotations. For all the entries we trained a non-linear classifier with 3 fully connected layers (similar to Table 1) on top of the feature maps generated by the 2nd conv. block of a RotNet model with 4 conv. blocks in total. The reported results are from CIFAR-10."
- 표 (열: # Rotations | Rotations | CIFAR-10 Classification Accuracy)

| # Rotations | Rotations | CIFAR-10 Classification Accuracy |
|---|---|---|
| 4 | 0°, 90°, 180°, 270° | **89.06** |
| 8 | 0°, 45°, 90°, 135°, 180°, 225°, 270°, 315° | 88.51 |
| 2 | 0°, 180° | 87.46 |
| 2 | 90°, 270° | 85.52 |

- 출처: Gidaris et al., ICLR 2018.

**설명**
- 이 표는 **pretext task의 설계(몇 개의 회전을 쓸지)** 가 학습된 feature의 질에 어떻게 영향을 주는지 보는 ablation임. feature 평가는 RotNet(4 conv block)의 2번째 conv block 출력 위에 3-layer FC non-linear classifier를 얹어 CIFAR-10 분류 정확도로 측정함. 즉 "pretext 정확도"가 아니라 **downstream 분류 정확도**를 보는 것.
- 관찰 1: 4 rotation(0/90/180/270)이 가장 높음(89.06). 8 rotation(45° 간격)은 오히려 약간 낮음(88.51) → 클래스를 늘린다고 더 좋은 건 아님. 45° 회전은 이미지 모서리가 잘리거나 빈 영역(padding)이 생겨 **인위적 artifact**가 생기고, 90° 배수 회전과 달리 pixel grid가 보존되지 않음.
- 관찰 2: 2 rotation 중에서는 {0°,180°}(87.46)가 {90°,270°}(85.52)보다 높음. 해석: 0° vs 180°는 "위아래 뒤집힘" 판단이고, 90° vs 270°는 둘 다 옆으로 누운 상태라 구분하기 어렵고 얻는 정보가 적음. 또 2-class는 4-class보다 task가 쉬워 필요한 semantic이 덜함.
- 결론: **회전 4개**가 정보량(난이도)과 artifact 없음 사이의 sweet spot.

## Pretext Tasks (p.45)

**슬라이드 내용**
- 표 (Task | Core Question | Learned Concept)

| Task | Core Question | Learned Concept |
|---|---|---|
| Relative Position | Where is the neighboring patch? | Local Spatial Context |
| Jigsaw | How should patches be arranged? | Global Spatial Structure |
| Inpainting | What is missing? | Context & Object Parts |
| Colorization | What color should it be? | Object Semantics |
| Rotation | Which orientation is correct? | Object-Centric Understanding |

**설명**
- 앞에서 다룬 5개 pretext task를 "무엇을 묻는가 → 어떤 개념을 배우는가"로 한 줄 요약한 표.
- **Relative Position** (Doersch 2015): 중심 patch 대비 이웃 patch의 상대 위치(8방향) 예측 → 인접 patch 간 **국소 공간 관계**.
- **Jigsaw** (Noroozi & Favaro 2016): 섞인 patch들의 permutation 예측 → 모든 patch 간 배열을 알아야 하므로 **전역 공간 구조**(object 전체의 part 배치).
- **Inpainting** (Pathak 2016, Context Encoders): 가려진 영역 복원 → 주변 **context**와 object의 part 구조 이해.
- **Colorization** (Zhang 2016): grayscale → color 예측 → 색은 object 종류에 의존(하늘=파랑, 잔디=초록)하므로 **object semantics**.
- **Rotation** (Gidaris 2018): 올바른 방향 판별 → object의 정상 자세를 알아야 하므로 **object-centric** 이해.
- 흐름: local → global → context/part → semantic → object-centric 순으로 점점 high-level 개념을 요구하는 구조로 읽을 수 있음.

## Pretext Tasks (p.46)

**슬라이드 내용**
- Pretext tasks focus on "**visual common sense**", e.g., predict rotations, inpainting, rearrangement, and colorization.
- The models are forced learn good features about natural images, e.g., semantic representation of an object category, in order to solve the pretext tasks. ← "forced learn" 은 "forced to learn" 의 오타로 보임
- We often do not care about the performance of these pretext tasks, but rather how useful the learned features are for downstream tasks (classification, detection, segmentation).
- **Problems: 1) coming up with individual pretext tasks is tedious.**

**설명**
- **visual common sense**: 사람이 당연히 아는 시각적 상식(물체는 똑바로 서 있음, 하늘은 위에 있음, 잔디는 초록 등)을 맞히게 하는 과제들을 통칭함. 이 상식을 풀려면 모델이 자연 이미지의 구조/semantics를 내재화해야 함.
- 핵심 관점: pretext task 자체의 정확도는 **목적이 아님**. 평가는 항상 learned feature를 downstream task(classification, detection, segmentation)에 transfer했을 때의 성능으로 함. pretext는 feature를 만들기 위한 "수단"일 뿐임.
- 문제점 1) **task마다 사람이 직접 설계해야 해서 번거로움(tedious)**. 새 domain마다 새 pretext를 고안해야 하며, 어떤 task가 좋은 feature를 만들지 사전에 알 수 없음. 슬라이드에는 "1)"만 있고 2)는 다음 슬라이드(Hope of Generalization)에서 이어지는 문제(pretext와 downstream의 정렬 가능성 문제)로 보임. ← 번호 1)만 있고 2)가 없음
- > 보충: 이 한계가 이후 contrastive learning(SimCLR, MoCo 등) 같은 **범용 SSL 목적함수**로 넘어가는 동기가 됨. 슬라이드 맥락상 다음 단원에서 다룰 것으로 추정되며, 슬라이드에는 명시되지 않음.

## The Hope of Generalization (p.47)

**슬라이드 내용**
- We really hope that the pre-training task and the transfer task are "aligned".
- 그림 (좌): "Pre-training — Weak or self-supervised". 해변의 나무 사진에 해시태그 "#sun #nofilter #fun #tree #aruba" (weak supervision 예시), 그 옆에 새 사진을 3x3 patch로 섞은 jigsaw 입력 → 화살표 → 올바르게 재배열된 새 사진.
- 그림 (우): "Transfer Tasks". PASCAL VOC류의 20개 클래스 이미지 그리드(aero, bicycle, bird, boat, bottle, bus, car, cat, chair, cow, diningtable, dog, horse, motorbike, person, plant, sheep, sofa, train, tv)와 또 다른 많은 이미지 썸네일 모음(대규모 데이터셋 느낌).
- Why should solving Jigsaw puzzles teach about "semantics"?
- Why should performing a non semantic task produce good features?

**설명**
- 핵심 가정: pre-training 단계의 task(예: jigsaw)가 transfer 단계의 task(예: 분류, detection)와 **"aligned"** 되어야 함, 즉 pretext를 잘 푸는 능력이 downstream에 유용한 능력과 겹쳐야 함. 이 정렬이 보장되지 않는다는 것이 pretext-task 기반 SSL의 근본적 불안.
- 두 질문은 이론적 근거가 약하다는 점을 비판적으로 제기함. Jigsaw는 semantic label과 무관한 **non-semantic task**인데, 왜 semantic을 요구하는 downstream(object recognition)에서 잘 작동해야 하는가? 사실상 "희망(hope)"에 기대는 방법이라는 것.
- weak supervision(해시태그)과 self-supervision(jigsaw)을 pre-training 범주로 함께 묶어 보여줌: 둘 다 사람이 정확히 label을 달지 않은 대규모 데이터에서 학습한다는 공통점.
- > 보충: 이런 제기는 이후 연구에서 "pretext task가 trivial shortcut(예: chromatic aberration, 경계 연속성)으로 풀릴 수 있다"는 문제(Doersch 2015, Noroozi 2016 등이 대응책 제시)와 연결됨. 슬라이드에는 없는 일반 지식임.

## The Hope of Generalization (p.48)

**슬라이드 내용**
- 그림 (좌) "Pre-training — Weak or self-supervised": 왼쪽의 "Pre-train data"(자연 이미지 썸네일 격자) → 화살표 → "ConvNet"(점점 작아지는 직육면체들로 그린 conv layers) → 화살표 → "Jigsaw" (pretext task 출력).
- 그림 (우) "Transfer": 실내(주방) 사진 한 장 → "ConvNet"(같은 구조) 에서 중간 conv layer 두 곳에서 위로 화살표가 올라가 파란 박스 2개 "Linear classifiers on "fixed" features" 로 연결됨.

**설명**
- p.47 개념을 구체적인 **2-stage pipeline** 으로 도식화함. (1) Pre-training: unlabeled pre-train data로 ConvNet을 jigsaw pretext task로 학습. (2) Transfer: 그 ConvNet을 **고정(fixed)** 하고, 중간 layer feature 위에 **linear classifier**만 학습해 downstream task에 적용.
- 이는 **linear probing (linear evaluation protocol)** 방식으로, feature 자체의 질을 순수하게 평가하기 위한 표준 방식임. fine-tuning보다 가혹하지만 representation 품질을 더 정직하게 보여줌. 여러 layer에 linear classifier를 붙여 보는 것은 **어느 깊이 layer가 transfer에 가장 유용한지** 보기 위함(pretext task에 특화된 마지막 layer는 덜 유용한 경우가 많음).
- > 보충: 이 그림은 Goyal et al. (2019), "Scaling and Benchmarking Self-Supervised Visual Representation Learning"(ICCV 2019, Facebook AI) 류의 그림으로 보이나 슬라이드에는 출처가 적혀 있지 않음. ← 출처 미표기

## EXAM POINTS

1. **Rotation Prediction 정의**: 이미지를 {0°, 90°, 180°, 270°}로 회전시켜 회전 각도를 4-class로 분류. 회전 각도가 곧 label → 사람 annotation 불필요. 목적은 $F^y(g(X,y))$ 확률 maximize(cross-entropy).
2. **왜 rotation이 좋은 feature를 만드는가**: 회전을 맞히려면 object를 localize하고 그 자세/semantic("위"가 어디인지)을 인식해야 하므로 object-centric representation이 학습됨.
3. **회전 개수 ablation**: 4 rotation(89.06) > 8 rotation(88.51) > {0°,180°}(87.46) > {90°,270°}(85.52). 4개가 가장 좋은 이유(45° 회전의 artifact, 2-class는 task가 쉬움 등)를 설명할 수 있어야 함.
4. **Downstream 평가 프로토콜**: pretext 정확도가 아니라 classification/detection/segmentation transfer 성능으로 평가. fc6-8만 학습 vs all fine-tuning의 의미 차이, ImageNet labels(상한)와 Random(하한) 기준선.
5. **5개 pretext task 비교 표** (Relative Position / Jigsaw / Inpainting / Colorization / Rotation 각각의 Core Question과 Learned Concept) 암기.
6. **visual common sense란 무엇이고, pretext task의 한계는?** 개별 task를 사람이 설계해야 해서 번거로움(tedious).
7. **Hope of Generalization**: pre-training task와 transfer task의 "alignment" 가정이 왜 문제인가? "Why should solving Jigsaw puzzles teach about semantics?"에 대해 논의할 수 있어야 함.
